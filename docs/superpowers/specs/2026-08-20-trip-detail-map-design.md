# 여행 상세 지도 모달

2026-08-20

## 문제

여행 표는 한 줄에 기간·목적지·박·최대거리만 보여준다. "그 기간에 어디를 어떻게 돌아다녔는지"는 볼 방법이 없다. 전체 지도는 여행마다 목적지 군집 대표점 하나만 찍기 때문에(`t.top`), 여행 안에서의 이동은 표현되지 않는다.

지금 상호작용도 단방향이다. 지도 마커에 마우스를 올리면 표 행이 하이라이트되지만(index.html:627-644), 표 행에는 클릭 핸들러가 없다.

## 목표

표의 여행 행을 클릭하면 모달이 열리고, 그 기간의 이동 경로를 지도에서 보여준다. 모달 하단의 날짜 축으로 하루씩 짚어볼 수 있다.

## 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 상세 표현 | 모달 오버레이 | 상세를 가장 크게 본다 |
| 배경 지도 | 기본 벡터, 타일은 옵트인 토글 | README가 "외부 API 호출 없음"을 약속한다. 타일 요청의 z/x/y는 곧 방문지 좌표이고 IP와 함께 제3자로 간다. 기본값으로 깨뜨릴 약속이 아니다 |
| 타일 제공자 | CARTO Positron | 밝은 저채도라 페이지 라이트 톤·파란 강조색과 맞고 경로선이 잘 뜬다. API 키 불필요, 경량 사용 무료. OSM 공식 타일 서버는 정책상 앱의 상시 사용을 권장하지 않는다 |
| 타임라인 | 날짜 축 + 시간순 경로 | 하루 단위로 짚고, 경로는 실제 시간순으로 잇는다 |
| 지도 구현 | 기존 캔버스 방식 확장, 자동 맞춤 | 의존성 0 유지. 팬·줌은 넣지 않는다 |
| 토글 노출 | 항상 | 조건부 노출은 사용자가 규칙을 학습해야 한다 |
| 날짜 칩 지명 | 그 날 지점이 가장 많은 군집 | 집에서 가장 먼 지점보다 그 날 실제로 보낸 곳을 대표한다 |

## 제약: 투영이 메르카토르가 아니다

기존 `draw()`의 투영은 정거원통도법에 cos(중위도)로 가로만 줄인 방식이다 (index.html:520-522).

```js
const kx=Math.cos((b+t)/2*D), dw=(r-l)*kx, dh=t-b;
const sc=Math.min(W/dw,Hpx/dh), ox=(W-dw*sc)/2, oy=(Hpx-dh*sc)/2;
const X=lo=>ox+(lo-l)*kx*sc, Y=la=>oy+(t-la)*sc;
```

CARTO·OSM 타일은 웹 메르카토르(EPSG:3857)다. 기존 `X`/`Y`를 그대로 쓰면 타일과 폴리곤·경로가 어긋난다. 모달은 자체 투영 함수를 가진다. 벡터 배경도 같은 메르카토르로 그려서 타일을 켰다 껐다 해도 정합이 유지된다.

## 제약: 하루 안 시간 순서가 없다

`analyse`는 좌표를 날짜 바구니에 담으면서 시각을 버린다 (index.html:335-340).

```js
for(const[t,p,off]of pts){
  const d=dayOf(t,p,off);
  if(!days.has(d)) days.set(d,[]);
  days.get(d).push(p);
}
```

그래서 하루 안 지점의 순서는 파일 기록 순서에 의존한다. 대개 시간순이지만 보장은 없다.

**해결**: 바구니에 담기 전에 `pts`를 시각으로 한 번 정렬한다. 추가 저장은 없고, 각 날짜 배열이 그대로 그 날의 시간순 경로가 된다. `trips()`의 `sum()`과 `dmax` 계산은 모두 순서에 무관하므로 영향이 없다.

## 제약: "무엇을 했는지"는 알 수 없다

현재 파서가 내보내기에서 꺼내는 것은 좌표와 `semanticType`뿐이다 (index.html:266-271). 타임라인에 붙일 설명은 우리 지오코더가 좌표에 붙인 지명 수준이며, 활동 라벨은 나오지 않는다. 실제 내보내기 파일에 더 풍부한 필드가 있는지는 진짜 파일로 확인해야 한다.

## 구조

세 단위로 나눈다. 각각 독립적으로 이해·교체 가능해야 한다.

### 1. 투영 (`merc`, `fitTrip`)

- `merc(lat, lon, z)` → 웹 메르카토르 픽셀 좌표
- `fitTrip(points, W, H)` → `{z, ox, oy}`. 여행 지점 전체를 캔버스에 담는 줌과 오프셋
- 줌은 `0 ~ 16`으로 자른다. 상한이 없으면 한 건물 안에 머문 여행에서 과도하게 확대되고 타일 요청도 늘어난다
- 경계가 한 점이거나 지나치게 좁으면 최소 스팬 **0.02도**(약 2km)를 강제한다
- 순수 함수. 캔버스도 DOM도 모른다

### 2. 배경 레이어

- **벡터** (기본): `REG`에 이미 로드된 해당 국가 폴리곤을 위 투영으로 그린다. 여행 국가의 지역 파일은 분석 시점에 이미 로드돼 있다 (index.html:159)
- **타일** (옵트인): 보이는 픽셀 영역에 걸치는 z/x/y만 `Image`로 요청해 캔버스에 그린다. 도착할 때마다 다시 그린다
- 인터페이스: `drawBackdrop(g, view, useTiles)`. 호출자는 어느 레이어인지 신경 쓰지 않는다

### 3. 경로와 마커

- **입력은 `ST.days`에서 `t.a ~ t.b` 범위의 모든 지점**이다. `trips()`의 `sum()`이 쓰는 `fp`(집에서 기준거리 밖인 지점만)가 아니다. 집을 떠나는 구간과 돌아오는 구간이 경로에 있어야 이동이 읽힌다
- 날짜별 폴리라인. 첫날이 가장 옅고 마지막 날이 가장 진한 파랑 램프로 진행 방향을 보이게 한다
- 목적지 군집(`t.top`) 마커, 집이 범위 안이면 집 마커
- 선택된 날짜만 진하게, 나머지는 흐리게

## 모달

- **헤더**: `2025.03.07 ~ 03.11 · 4박` + 목적지 이름 + 최대거리 + 해외 배지. 표 행과 같은 정보
- **본문**: 미니맵. 우측 상단에 `배경 지도` 토글
- **하단**: 하루당 칩 하나 (`03.07` + 그 날 대표 지명). 호버·클릭하면 그 날 구간만 강조. 기록이 없는 날은 빈 칩으로 남겨 공백이 보이게 한다
- **열기**: 표 행 클릭, 지도 마커 클릭
- **닫기**: X 버튼, Esc, 배경 클릭

### 배경 지도 토글

- 기본 오프. 선택은 `localStorage`에 기억해서 여행마다 다시 켜지 않아도 되게 한다
- 처음 켤 때 한 줄 고지: "지도 타일을 CARTO에서 받아옵니다. 보고 있는 지역의 좌표가 해당 서버로 전달됩니다."
- 켜져 있는 동안 `© OpenStreetMap contributors © CARTO` 표기

## 엣지 케이스

- **당일치기**: 칩 하나. 경로가 점 몇 개뿐이면 마커만 보인다
- **기록 공백일**: 날짜만 적고 지명 자리는 비운 흐린 칩으로 남긴다. 앞뒤 날의 지점을 이어 메우지 않는다
- **비행 구간**: 두 점을 직선으로 이으면 실제 경로가 아니다. 램프 색과 날짜 칩으로 "점을 이은 것"임이 읽히게 두고 별도 처리는 하지 않는다
- **경계가 한 점**: `fitTrip`이 최소 스팬을 강제한다
- **해외 여행**: 해당 국가 `regions` 파일이 이미 로드돼 있어 벡터 배경도 나온다
- **타일 요청 실패**: 벡터 배경 위에 경로만 그린다. 조용히 넘어간다

## 테스트

`test.js`는 스텁 DOM에서 스크립트를 실행하는 구조라 모달 조작은 검증할 수 없다. 순수 함수만 본다.

- `merc`가 알려진 기준값과 맞는지 (예: 적도·본초자오선이 타일 격자 중앙)
- `fitTrip`이 주어진 지점 전체를 캔버스 경계 안에 넣는지
- `pts` 정렬 후 각 날짜 배열이 시간순인지
- 정렬 추가가 기존 15개 검사를 깨뜨리지 않는지
